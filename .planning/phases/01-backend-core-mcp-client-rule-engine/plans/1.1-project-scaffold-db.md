# Plan 1.1: Project Scaffold + Database

## Scope

Set up the backend project skeleton and data layer. This is the foundation all other plans build on.

## Requirements

- R-06 (Backend — well structured, follows spec)
- R-07 (Database — integrated, multi-environment, documented)
- NFR-7 (Containerized deployment — SQLite local, Postgres prod via DATABASE_URL)

## Code deliverables

### 1.1.1 — pyproject.toml + project config
- `backend/pyproject.toml` with dependencies: `fastapi`, `uvicorn[standard]`, `sqlalchemy`, `alembic`, `pydantic`, `pydantic-settings`, `psycopg2-binary` (for Postgres), `httpx` (for test client), `pytest`, `pytest-asyncio`
- `backend/app/__init__.py`, `main.py` — FastAPI app factory with lifespan
- `backend/app/config.py` — `Settings` class reading `DATABASE_URL`, defaults to SQLite, overridable via env var
- `backend/app/database.py` — async engine + session factory, session dependency

### 1.1.2 — SQLAlchemy models
- `backend/app/models/__init__.py` — re-export all models
- `backend/app/models/scan_target.py` — `ScanTarget`: id, name, transport (enum: stdio/http), command, args (JSON), url, allow_external, created_at
- `backend/app/models/scan.py` — `Scan`: id, target_id (FK), status (enum: pending/running/completed/failed), error (nullable), raw_snapshot (JSON — stored for diffing), created_at, finished_at
- `backend/app/models/finding.py` — `Finding`: id, scan_id (FK), rule_id, severity (enum: critical/high/medium/low), title, description, remediation, subject (nullable)
- Relationships: Scan → ScanTarget (M:1), Scan → Finding (1:M)

### 1.1.3 — Alembic migration
- `backend/alembic/env.py` — reads DATABASE_URL from settings
- Initial auto-generated migration creating all 3 tables
- `backend/alembic.ini` — configured for migration directory

### 1.1.4 — Health endpoint
- `backend/app/routers/__init__.py`
- `backend/app/routers/health.py` — `GET /api/health` returns `{"status": "ok"}`

## Test deliverables

### Unit tests
- `backend/tests/unit/test_models.py` — test model creation, relationships, constraint enforcement (e.g. nullable fields, enum values)
- `backend/tests/unit/test_config.py` — test Settings reads DATABASE_URL correctly, defaults to SQLite

### Smoke test
- `backend/tests/unit/test_health.py` — TestClient GET /api/health asserts 200 + `{"status": "ok"}`

### Test infrastructure (shared across all plans)
- `backend/tests/conftest.py` — test session with SQLite in-memory DB, TestClient fixture, model factories

## Verification

```bash
cd backend && uv sync && uv run pytest tests/unit/ -v
# Expected: all tests green (models, config, health)
```

## Dependencies

None — this is the bootstrap plan.
