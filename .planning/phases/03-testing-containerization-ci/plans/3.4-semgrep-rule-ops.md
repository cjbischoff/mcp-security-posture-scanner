# Plan 3.4: Semgrep Custom Rule + Ops

## Scope

Create the `no-llm-on-untrusted-mcp-data` Semgrep rule enforcing the deterministic engine constraint, add a `/api/metrics` endpoint, and capture ops sample output.

## Requirements

- R-13 (Security/Audit/DevOps — 5 artifact types: Semgrep custom rule + ops output)
- NFR-1 (Deterministic engine constraint — the custom rule enforces this)

## Critical items tested

- Semgrep rule passes on current codebase (no false positives)
- Rule would flag any code that sends target-derived data to an LLM
- `/api/metrics` returns basic scan metrics
- Ops sample output captured to `ops/` directory

## Code deliverables

### 3.4.1 — Semgrep custom rule
- `security/semgrep/rules/no-llm-on-untrusted-mcp-data.yaml`:
  - Patterns that detect: any HTTP request with body containing MCP snapshot data (tools, resources, prompts, descriptions, schemas, findings text)
  - Focus on the rule engine and MCP client — any `httpx.post`/`requests.post`/`openai` call where the body could include untrusted target data
  - Metadata: `severity: ERROR`, `cwe: CWE-912` (Backdoor), references to PRD Section 2 item 1

### 3.4.2 — /api/metrics endpoint
- Add GET `/api/metrics` to `backend/app/routers/__init__.py`:
  - Returns basic Prometheus-style text or JSON with:
    - `scan_count_total`
    - `finding_count_total`
    - `rule_count_total`

### 3.4.3 — Ops sample output
- `ops/health-sample-output.md` — captured output from:
  - `curl localhost:8000/api/health`
  - `curl localhost:8000/api/metrics`
  - `docker compose ps`
  - Brief operational notes
