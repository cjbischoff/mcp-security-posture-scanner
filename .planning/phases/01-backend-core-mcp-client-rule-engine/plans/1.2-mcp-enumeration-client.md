# Plan 1.2: MCP Enumeration Client

## Scope

Build the MCP client that connects to a target server (stdio command or HTTP URL) and enumerates its tools, resources, and prompts. Returns a typed snapshot — never calls a tool.

## Requirements

- FR-2 (Enumerate MCP server metadata — list_tools, list_resources, list_prompts, schemas/descriptions only)
- NFR-2 (Enumerate-only safety boundary — never call_tool, read_resource, or execute prompts)

## Code deliverables

### 1.2.1 — MCP client module
- `backend/app/mcp_client/__init__.py`
- `backend/app/mcp_client/client.py` — `MCPClient` class with:
  - `connect_stdio(command, args)` — spawns subprocess, initializes MCP stdio transport
  - `connect_http(url)` — connects via streamable HTTP transport
  - `enumerate()` — calls `list_tools()`, `list_resources()`, `list_prompts()` in sequence
  - Returns `MCPSnapshot` (typed dict): `{tools: [...], resources: [...], prompts: [...]}` with metadata and schema
- `backend/app/mcp_client/models.py` — typed models: `MCPSnapshot`, `MCPTool`, `MCPResource`, `MCPPrompt` matching the MCP protocol response shapes
- Error handling: connection failures, timeouts, protocol errors → wrapped as `MCPClientError`

### 1.2.2 — Fixture MCP server (for testing)
- `backend/tests/fixtures/stub_mcp_server.py` — a minimal stdio-based MCP server using `mcp` SDK that:
  - Exposes 2-3 tools with known-vulnerable patterns (injected description text, unconstrained schemas, missing hints)
  - Exposes 1 resource with broad URI
  - Exposes 1 prompt
  - Serves as the integration test target — never changes after its initial definition

## Test deliverables

### Unit tests
- `backend/tests/unit/test_mcp_client.py` — test client initialization, error handling, parse logic (mock the transport layer)

### Integration tests
- `backend/tests/integration/test_mcp_client.py` — spawn the stub fixture server via subprocess, connect via stdio, enumerate, assert all 3 types returned, assert known-vulnerable patterns present
