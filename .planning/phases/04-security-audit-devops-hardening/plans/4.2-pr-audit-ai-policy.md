# Plan 4.2: PR Audit Log + AI Tool Data Policy

## Scope

Create two Phase 4 security artifacts: the PR audit log (documenting the code review process used during development) and the AI tool/data policy document (stating what data flows to external services).

## Requirements

- R-13 (Security/Audit/DevOps — artifact types: PR audit, AI tool data policy)
- PRD Section 8 (five required artifact types)

## Critical items tested

- PR audit log accurately describes the review methodology used
- AI tool data policy states:
  - Development-time: code was shared with an AI coding assistant, no secrets or credentials
  - Runtime: the core rule engine sends nothing to an LLM; Phase 5 decision model sends only counts + rule IDs
  - No target-server data (descriptions, schemas, tool names) ever leaves the host

## Code deliverables

### 4.2.1 — PR audit log
- `security/pr-audit/README.md` — describes:
  - Code review methodology (manual review of every AI-generated diff before commit)
  - Conventional commit format (type(scope): description)
  - GPG-signed commits
  - Verification gate: all tests must pass before acceptance
- `security/pr-audit/review-log.md` — log entries for each phase's review
  - Phase 0: operator reviewed scope, corrected over-eager Phase 1 start
  - Phase 1 operator approved plan breakdown; all 86 tests verified
  - Phase 2: operator approved frontend decomposition; 26 frontend tests verified
  - Phase 3: operator approved containerization approach; compose verified

### 4.2.2 — AI tool data policy
- `security/ai-tool-data-policy.md` — states:
  - **Development:** AI coding assistant (Claude Code) had access to code, docs, and planning artifacts. No secrets, API keys, credentials, or personal data were shared. All generated code was reviewed before commit.
  - **Runtime — scan engine:** No target-server data (descriptions, schemas, tool/resource/prompt metadata) is sent to any LLM. The rule engine is deterministic (regex, heuristic, schema-shape based). This is enforced by custom Semgrep rule `no-llm-on-untrusted-mcp-data`.
  - **Runtime — decision model (Phase 5):** If configured, only scanner-derived counts (findings per severity) and rule IDs (enums from the fixed set MCP-001..MCP-010) are sent to the hosted model. Target-server text is never included. The model is opt-in via environment variables.
  - **Third-party services:** GitHub Actions (CI/CD). No other runtime data sharing.

## Test deliverables

### Verification by inspection
1. PR audit log entries match actual development history
2. AI data policy claims are accurate and match the codebase (no false claims about what data leaves the host)

## Dependencies

- All prior phases (accurate review log requires complete history)
