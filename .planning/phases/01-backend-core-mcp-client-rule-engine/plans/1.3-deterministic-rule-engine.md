# Plan 1.3: Deterministic Rule Engine

## Scope

Implement all 10 deterministic rules (MCP-001 through MCP-010), one module per rule, plus the orchestrator that runs them against an MCPSnapshot.

## Requirements

- FR-3 (Run deterministic rule engine — 10 rules, pattern/heuristic/schema based, no LLM)
- MCP-001 through MCP-010 (individual rule checks)
- NFR-1 (Deterministic engine constraint — never feeds target data to an LLM)
- NFR-4 (Clean-room — rules from public sources only)
- NFR-5 (Capped rule set — exactly 10 for v1)

## Code deliverables

### 1.3.1 — Rule base + orchestrator
- `backend/app/rules/__init__.py` — base `Rule` class with `check(snapshot: MCPSnapshot) -> list[Finding]` interface, rule metadata (id, severity, description, remediation)
- `backend/app/rules/orchestrator.py` — `run_all_rules(snapshot)` iterates all registered rules, collects findings, returns deduplicated list

### 1.3.2 — Individual rule modules (one file per rule)

| Rule | File | Check logic | Severity |
|---|---|---|---|
| MCP-001 | `backend/app/rules/mcp001_injection.py` | Regex for hidden unicode (zero-width chars), "ignore previous instructions", "ignore all rules", system prompt override patterns in tool descriptions | Critical |
| MCP-002 | `backend/app/rules/mcp002_unconstrained_schema.py` | Scan tool input schemas for parameters named `command`, `path`, `url`, `shell`, `exec` without pattern/format/enum constraints | High |
| MCP-003 | `backend/app/rules/mcp003_missing_annotations.py` | Check tool schemas for absence of `readOnlyHint`/`destructiveHint` annotations | Medium |
| MCP-004 | `backend/app/rules/mcp004_read_write_pairing.py` | Signal if any tool reads data and another writes data on the same capability surface (confused-deputy) | High |
| MCP-005 | `backend/app/rules/mcp005_unauthenticated.py` | HTTP transport with no auth scheme in server info | High |
| MCP-006 | `backend/app/rules/mcp006_broad_resource_uri.py` | Detect resource URI patterns with wildcards (`*`, `**`), root-only paths | Medium |
| MCP-007 | `backend/app/rules/mcp007_description_anomaly.py` | Flag tool descriptions with outlier length (>2000 chars) or high character entropy (potential hidden payload) | Medium |
| MCP-008 | `backend/app/rules/mcp008_missing_schema.py` | Check required parameters lack schema validation (no type, no constraints) | Medium |
| MCP-009 | `backend/app/rules/mcp009_resource_injection.py` | Same injection patterns as MCP-001 but applied to resource/prompt content descriptions | Critical |
| MCP-010 | `backend/app/rules/mcp010_drift.py` | Diff-only rule: compare two snapshots, flag findings that changed severity or disappeared without description change | High |

### 1.3.3 — Rule registry
- `backend/app/rules/registry.py` — imports all 10 rule modules, provides a list of rule instances for the orchestrator
