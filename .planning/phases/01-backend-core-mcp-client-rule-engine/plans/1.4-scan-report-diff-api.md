# Plan 1.4: Scan/Report/Diff API + Services

## Scope

Build all Phase 1 API endpoints: submit scan, poll status, get report, diff scans. Wire up the MCP client and rule engine into an async background task. Enforce consent for external targets.

## Requirements

- FR-1 (Submit and run a scan — POST /api/scans, async, returns scan ID)
- FR-4 (Produce scored findings report — GET /api/scans/{id}/report, severity-grouped)
- FR-5 (Diff two scans — GET /api/scans/{id}/diff/{other_id}, added/removed/unchanged + drift)
- FR-7 (Target consent — allow_external flag required for non-localhost URLs)
- NFR-3 (Localhost/fixture default — consent enforcement)

## Code deliverables

### 1.4.1 — Services layer
- `backend/app/services/__init__.py`
- `backend/app/services/scan_service.py` — `create_and_run_scan(target_data)`:
  1. Create/lookup ScanTarget (reuse by name)
  2. Create Scan(status=pending)
  3. Launch background task (asyncio or FastAPI BackgroundTasks):
     - Set Scan(status=running)
     - Initialize MCPClient (stdio or HTTP based on transport)
     - Call `client.enumerate()` → get MCPSnapshot
     - Store raw_snapshot on Scan
     - Run rule orchestrator against snapshot → list of Findings
     - Bulk save Findings
     - Set Scan(status=completed, finished_at=now)
  4. Return Scan ID immediately
- `backend/app/services/report_service.py` — `get_report(scan_id)` — loads Scan + Findings, groups by severity, returns Report
- `backend/app/services/diff_service.py` — `diff_scans(scan_id, other_id)`:
  - Validate both scans exist, completed, same target
  - Key findings by (rule_id, subject)
  - Compute added/removed/unchanged
  - Run MCP-010 drift detection across snapshots
  - Return ScanDiff

### 1.4.2 — Routers
- `backend/app/routers/scans.py` — all scan-related endpoints:
  - `POST /api/scans` — validate target, enforce consent check (reject non-localhost without allow_external), delegate to scan_service, return 201 with Scan
  - `GET /api/scans` — list scans, newest first
  - `GET /api/scans/{scan_id}` — scan status + metadata
  - `GET /api/scans/{scan_id}/report` — findings report (409 if not completed)
  - `GET /api/scans/{scan_id}/diff/{other_id}` — diff (409 if either not completed or different targets)

### 1.4.3 — Consent validation
- `backend/app/services/consent.py` — `validate_target(target)`:
  - If transport=http and URL host is not localhost/127.0.0.1 and allow_external=false → raise consent error
  - Consent flag is logged per PRD Section 2 item 2

### 1.4.4 — Repositories layer
- `backend/app/repositories/__init__.py`
- `backend/app/repositories/scan_repo.py` — CRUD for Scan, ScanTarget
- `backend/app/repositories/finding_repo.py` — bulk insert, query by scan_id

## Test deliverables

### Unit tests
- `backend/tests/unit/test_consent.py` — localhost allowed without flag, external rejected without flag, external allowed with flag, edge cases
- `backend/tests/unit/test_diff_service.py` — mock findings, test added/removed/unchanged grouping, drift detection
- `backend/tests/unit/test_scan_service.py` — mock MCP client + rule orchestrator, test scan lifecycle transitions

### Integration tests
- `backend/tests/integration/test_scan_flow.py` — full end-to-end via TestClient:
  1. POST /api/scans with stdio fixture server target → 201 + scan ID
  2. GET /api/scans/{id} → status progresses to completed
  3. GET /api/scans/{id}/report → findings with known-vulnerable detections
  4. POST a second scan against same fixture
  5. GET /api/scans/{id}/diff/{other_id} → diff structure matches expectations
  6. POST /api/scans with external URL without allow_external → 422 consent error
  7. POST /api/scans with external URL with allow_external=true → 201
